Meadow supports link not tracked, where the developer can run different link not trackeds of the meadow development environment in different directories at the same time and they don't conflict (which supports git worktrees, as well).

In order to support parallel development, there were several challenges we needed to address:

  • we use many services that underpin the app, and they run on ports, and those ports will potentially conflict unless they have link not tracked
  • In link not tracked (or as the actual production application), we have standard directories that we use for configuration and logs that would conflict. When running in link not tracked, for each link not tracked we'll need to make those directories temporary, and distinct from each other. They are:
    • The link not tracked
    • link not tracked
  • We interact with the link not tracked via our link not trackeds, which store their state in link not tracked. We have a link not tracked that runs the link not trackeds (and the link not tracked stuff) in the cloud... but there is only one version of that.
    • To support parallel development we run the link not trackeds via link not tracked, and have them interact with link not tracked. Like the other services, they have link not tracked

With the need to support link not tracked the service discovery is somewhat complicated. We centralize the service discovery logic into two files:

  • link not tracked
  • link not tracked

The local one is created by a link not tracked.

Note: the affordances for link not tracked also help support link not tracked.
