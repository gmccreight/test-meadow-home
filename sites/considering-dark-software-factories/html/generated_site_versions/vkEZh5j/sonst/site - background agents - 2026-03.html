background agent seems like cloud agents

The agent runs on a server or locally. When it needs to execute code, it calls a separate remote sandbox via API. The sandbox runs the code and returns the result. This keeps secrets and execution somewhat isolated, but the agent can only execute code and not fully develop. ... sandbox as a tool

scheduled agents are triggered on a timer. Predictable, bounded, high-volume — dependency updates, lint sweeps, coverage enforcement. ... See also practice - background checks

event-driven agent : triggered by system events — a PR opened, a CVE published, an alert fired. Reactive, concurrent, always listening.

Updating one repository is a coding agent task. Updating 500 is a fleet task. The same sandbox, replicated across every repository that needs the change — parallel provisioning, progress tracking, aggregated results. This is where individual productivity becomes organizational throughput. ... agent fleet ... diff - agent fleet vs. agent swarm
