### Status 🟡

I've just started doing this and it _seems_ very compelling.  The prerequisite is that you have [[practice - context right in the repo|context right in the repo]], which I do, but the story is imperfect so far.  [[person - Matt Pocock]]'s [[agent skill -- grill-with-docs]] suggests a specific structure... a `CONTEXT.md` file.

In [[b OpenAI harness engineering 2026-02]], in the section about documentation there is a quote about when everything is important nothing is important.  It also describes how [[documentation skews from code]] is inevitable in a large document because it's impossible to do things like cross-check links, look at metadata around how recently something was updated, etc.  So they suggest breaking things apart into what I call a [[documentation context graph]].  I think that's probably superior to the `CONTEXT.md` file being advocated by Matt.
