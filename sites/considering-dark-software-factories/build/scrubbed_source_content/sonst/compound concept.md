Basically, compounding two or more concepts into a higher-level concept.

In notes, I create these concepts by restating the note title in a <span class="link-not-tracked">link not tracked</span>.

### How big should the compound concepts be?

It can be challenging to create [[well-factored notes]].  Ideally you want the biggest compound concept that can be used broadly, and is unconditionally applicable wherever it is used.

Here's an example.  Let's consider [[coding pattern -- guard the edges so you can code within the happy zone]].  It is comprised of [[coding concept - guard the edges]] and [[coding concept -- the happy zone]], which are <span class="link-not-tracked">link not tracked</span>s that are independently useful, but they often travel together.  Rather than copying them both in numerous places to describe the idea that "guard the edges so you can have a happy zone", we just make that compound concept a note, then use that, instead.  That "finding and using things at the right level of abstraction" should feel pretty natural to anyone who codes a lot.
