As [[agentic coding]] improves, the scarce human contribution shifts from typing implementation code to deciding what should exist, what constraints matter, and what quality means in this system.

A coding agent can generate large amounts of plausible code quickly. That only compounds into good software when the human gives it <span class="link-not-tracked">link not tracked</span>: the desired shape of the system, stable boundaries, important [[invariant]]s, verification strategy, and the tradeoffs that should stay true across many local changes.

The human should not need to micromanage every implementation choice. The better pattern is to describe a [[desired state]], encode [[guardrail]]s, and let the agent reconcile the current code toward that state. The human's <span class="link-not-tracked">link not tracked</span> shows up in choosing the constraints, noticing when a solution is locally plausible but globally wrong, and knowing <span class="link-not-tracked">link not tracked</span> before the agent can reliably produce it.

Can also help to have human-specified [[code interface]]s.

This is why [[app specification]] and [[app verification]] become central in an AI-heavy software workflow. Code generation gets cheaper, but direction and judgment remain load-bearing. Without them, agentic coding produces motion; with them, it can produce coherent systems.
